# Engineering Writing Failure Modes

## Thin Evidence

Risk: the user asks for a complete section from vague claims.

Response:

- State missing inputs.
- Use placeholders or a draft outline.
- Do not invent numbers, datasets, baselines, citations, or mechanisms.

## Stronger-Than-Evidence Claims

Risk: the user asks to make the contribution sound more novel, robust, or
general than the evidence supports.

Response:

- Downgrade the verb.
- Add the boundary.
- Identify the evidence needed for the stronger version.

## Citation Fabrication

Risk: the user asks for plausible references or common papers without providing
sources or a search tool.

Response:

- Refuse to fabricate citations.
- Add citation placeholders or ask to run a source-grounded search.

## Wrong Skill

Risk: the task is pure polish, captions, reviewer responses, or readiness
checking.

Response:

- Name the more appropriate skill.
- Continue only if the user explicitly asks for a combined workflow.

## Methods Directory

Risk: Methods becomes a list of modules rather than a reader path.

Response: build overview, main object/signal, mechanism blocks, and
execution/fallback closure before drafting prose.

## Experiments Table Narration

Risk: Results simply rewrites each table cell.

Response: recover evaluation questions, overall result, condition axes,
ablation role, and failure boundary.

## Promotional Abstract

Risk: Abstract uses `robust`, `generalizable`, or `state of the art` without the
required evidence.

Response: downgrade to the tested condition and name the missing evidence.

## Conclusion New Claim

Risk: Conclusion introduces a new baseline, metric, mechanism, or future work
not anchored earlier.

Response: remove it or move it to the section where evidence can be supplied.
