# Paper Workflow

Use this when starting from notes, rebuilding an existing draft, or deciding
what to write first.

## Do Not Start with the Abstract

For an engineering systems or robotics paper, use this order:

1. lock the one-sentence thesis
2. define figure/table responsibilities and evidence map
3. write Methods
4. write Experiments/Results
5. write Introduction
6. decide whether Related Work is folded or standalone
7. write Abstract and Conclusion
8. run figure, wording, citation, and build validation

The Abstract should only promise what Methods and Experiments can support.

## Three-Window Rule

Before writing in an existing manuscript, inspect:

| Window | Purpose | Guardrail |
|---|---|---|
| current live draft | see the current paper thesis and section role | do not edit an outdated copy |
| strong neighboring paper | learn section order and paragraph responsibility | do not copy wording |
| revision history/comments | learn what has already failed | do not reintroduce old errors |

If a sentence does not support the current thesis, does not have a paragraph
job, or repeats a known failure mode, do not add it.

## From Scratch

Produce two artifacts first:

1. one-sentence thesis
2. contribution-evidence table

Then build the paper around those artifacts. If the thesis changes, revisit
figures, Methods, Experiments, Introduction, and Conclusion.

## Existing Draft Revision

Do not begin with sentence polish. First inspect:

1. comment/revision history
2. figure/table responsibility
3. section boundaries
4. paragraph job
5. claim strength

Many ugly sentences are symptoms of misplaced structure.

## Neighbor-Paper Learning

When using 3-5 example papers, extract:

- section opening job
- paragraph sequence
- where formulas or evidence appear
- how failures/limitations are placed
- how the final claim is bounded

Do not extract:

- surface phrasing
- figure count
- table style alone
- fashionable model names
