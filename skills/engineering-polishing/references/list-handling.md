# List Handling

Use this when source material contains many applications, advantages, methods,
challenges, or chapter items.

## Do Not Expand Lists Mechanically

Avoid turning lists into:

```text
First, ... Second, ... Third, ...
```

unless the user explicitly asks for a numbered list.

## Find the Grouping Principle

Classify items by:

- application setting
- function
- structure type
- signal source
- process step
- model level
- evaluation metric
- control objective
- failure mode

Then merge related items into higher-level claims.

## Return to the Center

After listing examples, state what the list collectively shows:

- a shared limitation
- a research need
- a design constraint
- an evaluation axis
- a boundary of the method

## Advantages

Do not write every item as `has the advantage of`. Explain the relation between
advantage and requirement:

```text
Because [application] requires [constraint], [method property] is useful for
[specific role].
```

## Challenges

Group challenges into layers such as:

- theoretical basis
- structure or process constraint
- system integration
- validation and deployment

Then connect the layers to the paper's method or evaluation plan.
