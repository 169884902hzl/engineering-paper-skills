# Figure Roles

Use this when deciding what each figure should do.

## Motivation Figure

Job: show why the old or naive approach fails.

Should:

- be visually light
- focus on the failure mode
- motivate the problem

Should not:

- explain the full algorithm
- contain dense math
- claim evidence that appears only in experiments

## Framework Figure

Job: provide a system and information-flow map.

Should:

- define physical roles
- show data/control flow
- give the reader a Methods navigation path
- align visual modules with manuscript sections

It can have a heavier caption than a motivation figure because it carries
structure.

## Workflow Montage

Job: show an observable execution sequence.

Should:

- show time or phase order
- make handoff or failure recovery visible
- stay honest about what is visible

Should not:

- claim to prove hidden algebra or mechanisms
- replace Results evidence

## Object/Task Gallery

Job: make task or object difficulty axes visible.

Should:

- show representative examples
- connect to categories used in Results
- help readers understand why pooled averages are insufficient

## Evidence Figure

Job: support a specific quantitative or qualitative claim.

Should:

- state metric and comparison scope
- include uncertainty or sample count when needed
- be interpreted in Results text

If a figure cannot be mapped to a claim or reader action, remove or redesign it.
